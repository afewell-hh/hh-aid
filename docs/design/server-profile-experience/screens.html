Server profile experience: low-fidelity screens

D02 #9 server-class pass, static wireframes. These screens are not a calculator. Every quantity was entered by hand and is checked by bom-arithmetic.py. Every part is a generic placeholder or unverified sponsor shorthand, not a vendor-qualified SKU. Leaf and spine counts are deliberately shown as not estimated. Product terms such as fabric and leaf class are product language only; they are product intent, kept separate from the upstream Fabric object, domain and installation. The mapping follows bridge's draft source evidence (#3, PR #28 b4329a5, review pending) and is always an explicit choice, never inferred from a network's name. Field names are provisional until parts (#6) and model (#8) fixtures land. Rationale: server-profile-experience.md.

Server means any non-switch device attached to the fabric, including storage arrays, appliances and other endpoints, following Hedgehog's Server concept. The product UI explains this once, on F1.

E1 Both-ends comparison with explainable filters

E1Backend port (be1–be8, same pattern) ↔ backend-leaf port. Opened from the details panel with "Compare ends". The engineer is choosing the module for End B.

Filtering: candidate modules or assembly ends for End B, the backend-leaf port (host: leaf switch, model not chosen).

Filters: ☑ Fits End B's own host cage ☑ Fits End B's own host mode and electrical lanes ☑ Optical interface matches End A's module (PMD, reach, connector) ☐ Documented pairs only ☑ Show unknown ☐ Show mismatches Why is an option hidden?

Each filter names the component it tests and what it is tested against. Host fit is checked per end, against that end's own host: the End B module must fit the leaf port, and the End A module must fit the server NIC. End B is not required to share End A's cage form factor or electrical lane count just because it is the other end. Only the link-side attributes (optical PMD, reach, connector and fiber, or one integrated assembly) are compared across the two ends. With the leaf model not chosen, the host-fit filters for End B hide nothing and every option shows unknown for host fit: "Hidden: 0 for End B host fit (leaf model not chosen) · Hidden: 3 with a different optical interface from End A's module (source: class r1 PMD field)".

Unknown and evidence-backed mismatch are different states and are never merged. An override records an engineer decision; it does not change the verdict and is not qualification. A known mismatch is hidden from the compatible list but stays inspectable under "Show mismatches", with both values kept. It is never auto-corrected. Rule IDs follow parts CF1–CF7.
