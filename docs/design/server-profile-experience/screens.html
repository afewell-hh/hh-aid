Server profile experience: low-fidelity screens

D02 #9 server-class pass, static wireframes; sponsor iteration of main 2ee0e7d (allocation groups, summary BOM, connection-class review). These screens are not a calculator. Every quantity was entered by hand and is checked by bom-arithmetic.py. Every part is a generic placeholder or unverified sponsor shorthand, not a vendor-qualified SKU. Leaf and spine counts are deliberately shown as not estimated. Product terms such as fabric and leaf class are product language only; they are product intent, kept separate from the upstream Fabric object, domain and installation. The mapping uses only the core of bridge's source evidence that topo's review corroborated (#3, PR #28 b4329a5; corrections C1–C7 pending). It is always an explicit choice, never inferred from a network's name. Field names map to parts' accepted SU fields (#6, 0230cd8) and model's working contract (#8, 365a0c3); see the rationale, §6.1. Rationale: server-profile-experience.md.

Server means any non-switch device attached to the fabric, including storage arrays, appliances and other endpoints, following Hedgehog's Server concept. The product UI explains this once, on F1.

E1 Connection detail (optional drill-down from R1)

E1Backend port (be1–be8, same pattern) ↔ backend-leaf port. Opened from an R1 row with "Detail"; not required reading for the review. Selection context: the module for End B (alternatives: module for End A, or an entire assembly).

Filtering: candidate modules or assembly ends for End B, the backend-leaf port (host: leaf switch, model not chosen).

Filters: ☑ Fits End B's own host cage ☑ Fits End B's own host mode and electrical lanes ☑ Link-side check vs End A's module: hide evidence-backed mismatches only ☐ Prefer same PMD and connector as End A (search preference, not a compatibility rule) ☐ Documented pairs only ☑ Show unknown ☐ Show mismatches Why is an option hidden?

Each filter names the component it tests and what it is tested against. Host fit is checked per end, against that end's own host (cage, mode, power, FEC and firmware where known): the End B module must fit the leaf port, and the End A module must fit the server NIC. End B is not required to share End A's cage form factor or electrical lane count. The link side (PMD, wavelength, connector, polish, fiber, polarity, reach, or an assembly's end-to-group mapping) is an evidence check (parts CF2–CF4): it hides a candidate only for an evidence-backed mismatch; an unknown or unverified value gives unknown, never incompatible; matching labels are not evidence. "Same PMD and connector as End A" is only an optional search preference. Here the leaf model is not chosen and End A's PMD is a tentative class value, so nothing is hidden: "Hidden: 0 for End B host fit (leaf model not chosen) · Hidden: 0 by link-side check (End A PMD unverified; candidates show unknown)". "Why is an option hidden?" names the host, field and evidence for each rejection.
