Server profile experience: low-fidelity screens

D02 #9 server-class pass, static wireframes. These screens are not a calculator. Every quantity was entered by hand and is checked by bom-arithmetic.py. Every part is a generic placeholder or unverified sponsor shorthand, not a vendor-qualified SKU. Leaf and spine counts are deliberately shown as not estimated. Product terms such as fabric and leaf class are product language only; how they map to upstream Fabric, domain and plane objects is pending compat (#3). Field names are provisional until parts (#6) and model (#8) fixtures land. Rationale: server-profile-experience.md.

Server means any non-switch device attached to the fabric, including storage arrays, appliances and other endpoints, following Hedgehog's Server concept. The product UI explains this once, on F1.

Filter rules explain themselves. For example: "Hidden: 3 options with a different cage family from end A (source: class r1 cage field)". Unknown is shown unless the engineer filters it out, and the count of hidden options is always visible. A known mismatch is hidden from the compatible list but stays inspectable under "Show mismatches", with both values kept. It is never auto-corrected. Parts' SU-COMPARE-1 (DR4 at one end, FR4 at the other: same 400G, different optical interfaces) is the reference mismatch case. Rule IDs follow parts CF1–CF7.
